# MiniCity 城市重新规划 - 实施指南

## 📋 项目概述

本次规划旨在将 MiniCity 从一个功能分散的虚拟空间，重新组织为一个具有真实城市特征的有机系统，包含清晰的功能分区、层级化的道路系统和丰富的公共空间。

## 🎯 规划目标

1. **清晰的城市结构**：建立中心-外环-扩展区三层空间结构
2. **明确的功能分区**：CBD、文化区、科技区、居住区各司其职
3. **便捷的交通系统**：主干道-次干道-街巷三级道路体系
4. **丰富的公共空间**：广场、公园、绿地多层次开放空间
5. **鲜明的城市特色**：科技与文化融合的虚拟城市形象

## 📊 规划统计

- **总建筑数量**: 70 栋
- **需要移动**: 58 栋
- **保持不变**: 12 栋（北区建筑）
- **功能区数量**: 11 个主要功能区

## ⚠️ 注意事项

1. **坐标系统**
   - X轴：东西方向（西负东正）
   - Z轴：南北方向（南负北正）
   - 原点 (0, 0) 为城市中心

2. **道路避让**
   - 确保建筑不与主干道重叠
   - 保持建筑与道路的合理间距
   - 注意 `ROAD_COORDS` 定义的道路位置

3. **功能分区**
   - 相似功能的建筑应靠近
   - 保持功能区之间的过渡自然
   - 考虑市民的使用便利性

4. **地标可见性**
   - 地标建筑应位于开阔位置
   - 避免被其他建筑遮挡
   - 考虑天际线效果

5. **北区特殊性**
   - 北区已有完善规划，坐标保持不变
   - 包含居住区和文化设施
   - 有自己的道路网络系统

## 🔧 故障排除

### 如果更新失败

1. **恢复备份**
   ```bash
   git checkout backup-before-redesign
   git checkout -b master-restored
   ```

2. **手动修复**
   - 检查 `scripts/update-building-coordinates.js` 的错误信息
   - 手动编辑相应的建筑配置文件
   - 重新运行更新脚本

### 如果构建失败

1. **检查类型错误**
   ```bash
   npm run typecheck
   ```

2. **检查导入错误**
   - 确保所有建筑文件都存在
   - 检查 `_registry.ts` 中的导入

3. **清理并重建**
   ```bash
   rm -rf node_modules dist
   npm install
   npm run build
   ```

### 如果渲染异常

1. **检查坐标范围**
   - 确保所有坐标在合理范围内
   - 检查是否有超出 `CITY_LIMIT` 的建筑

2. **检查道路冲突**
   - 使用 `footprintOverlapsMainRoad` 检查
   - 调整建筑位置避免冲突
