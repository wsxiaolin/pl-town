# 物实市集与每日经济玩法

## 目标

把现有余额和四种剧情道具商店接成可持续的游玩循环：居民每天回来签到、逛不同建筑、完成委托，再把物实币花在当前剧情需要的道具上；富余的食材和合成品可以合成加工，或挂到居民交易所卖给其他居民。奖励在服务端校验并写入 SQLite；前端只展示服务器提供的余额、进度、商品价格和挂单账本。

## 玩家循环

1. 与南侧或西侧商场交互打开「物实市集」，查看余额、签到连胜、今日委托和轮换特惠。
2. 每个上海自然日领取一次签到币。首日 40 币；连续签到每天多 10 币，额外奖励最多 60 币，断签后从首日重新累计。
3. 当天第一次探访每一座已建成且可访问的建筑时，计入城市委托。探访 3 座可领 35 币，探访 6 座再领 90 币；相同建筑当天不会重复计数。
4. 在货架按需选择数量。商品分为食材与剧情道具；每日轮换一件商品打 75 折，批量购买也使用服务端计算的折后单价。
5. 在市集工坊按配方把食材合成加工品（热炖牛肉、龙井茶席、夜谈礼盒）；配方材料同时是剧情道具，居民可自行决定留用剧情还是合成。
6. 把加工品（或食材）交付给今日供货委托换取报酬；每个上海日每种订单只能交付一次。
7. 把可交易物品挂到居民交易所：上架即托管（物品离开背包），其他居民按挂单总价购买，货款全额转给卖方；卖方可随时下架取回物品。
8. 道具继续进入现有背包并供剧情消费；商店筛选、数量选择、余额不足状态和待处理状态都由当前云端进度驱动。

## 经济参数

| 项目 | 当前规则 |
| --- | --- |
| 新居民余额 | 1,200 币 |
| 每日签到 | 40 币 + 连续签到奖励；加成每次 10 币，最多 60 币 |
| 街巷漫游 | 当日探访 3 座不同建筑，奖励 35 币 |
| 城市寻宝 | 当日探访 6 座不同建筑，奖励 90 币 |
| 市集特惠 | 每个上海日轮换一种在售道具，折扣 25% |
| 商品数量 | 每笔 1–20 件；总价仍按服务器价格原子扣款 |
| 合成配方 | 热炖牛肉（牛肉×1＋萝卜×2）、龙井茶席（龙井茶×2）、夜谈礼盒（龙井茶×1＋音乐盒×1） |
| 供货委托 | 5 个订单按上海日轮换，报酬 85–210 币，每种每日限交付一次 |
| 交易所挂单 | 每人同时最多 6 个在售挂单；每单 1–20 件，单价 1–9,999 币 |

现有商品 ID 与基础价格保持不变：龙井茶 30、牛肉 45、萝卜 20、音乐盒 120。建筑解锁价格、已筹资城市项目 ID 和历史奖励定义都不在本次改动范围内。后台（世界配置页）仍可增删在售商品与调价；交易范围随在线目录实时变化——正在出售的商品与三类合成品始终可交易，商品分类中的「食材」由服务端按已知食材清单派生，后台自定义的新商品默认归入剧情道具货架。

## 服务端与数据

- `progression.ts` 提供今日委托、签到参数、轮换商品、配方与供货订单；特惠日、订单轮换均以 `Asia/Shanghai` 日期为准（`shanghaiTime.ts`）。
- WebSocket 消息：`progress.daily.checkin`、`progress.daily.mission.claim`、`market.recipe.craft`、`market.supply.fulfill`、`market.listings.get`、`market.listing.create/buy/cancel`。服务端根据用户记录发奖，重复领取返回未领取结果，不重复增加余额；挂单变更通过 `market.listings` 按人广播（含自己的挂单视图）。市集写操作有独立限流（40 次/10 秒）。
- `player_daily_economy` 保存当前日的签到状态、连续天数、当日去重探访清单、委托领取清单和供货交付清单。签到、任务领取、订单交付、钱包加币与每日状态更新放在同一 SQLite 事务内，上海日切换时全部按日重置。
- `market_listings` 是托管账本：创建挂单事务内先把物品从卖方背包扣出，购买在同一事务内完成买方按「单价 × 数量」扣款、卖方等额入账、物品转移与状态落库；下架原路退回物品。`price` 始终是单价，结算总额由服务端计算；`status` 只能在 `active/sold/cancelled` 间由服务端迁移，买家不能购买自己的挂单，余额不足时拒绝结算。该表是持久账本，不做按时间清理。
- 数据库 schema 从 6 升至 8，只新增 `player_daily_economy` 与 `market_listings` 两张表，不重写已有余额、背包或城市治理账本。旧备份没有这两张表时，正常启动会创建空表；旧备份里的现有进度仍按原表恢复。
- 特惠折扣由服务器重新比对当前日期、今日商品和前端随请求提交的 `dealDay`。请求过期或商品不匹配时按原价结算，客户端显示值不能决定扣款金额。

## 后续扩展方向

若要加入可摆放装饰、衣着或家具，应先实现对应的场景/外观消费效果，再把它们作为新的商品和持久化状态加入商城。需要跨设备幂等订单或交易回执时，应按永久账本记录设计并为历史备份提供显式迁移；不要用按时间清理在线记录的方式控制表容量。
